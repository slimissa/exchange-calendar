# JS-rendered exchange sweep — 2026-09-19

## Question
Are the 13 exchanges that BLOCKED.md labels "JS-rendered" actually blocked
by JS rendering, i.e. would a headless browser resolve them?

## Method
Playwright 1.63.0, headless Chromium, run from the maintainer's local machine
(single vantage point). Candidate URLs per exchange come from the registry
(`exchanges/<MIC>.json` `source_url`) and the BLOCKED.md `Checked:` line;
1 to 3 candidates each (XPHS 1, XQSE 3). Each URL was loaded with
`wait_until="domcontentloaded"` plus an 8 s wait (30 s navigation timeout).
Recorded: HTTP status, final URL, HTML bytes, matched terms, and anti-bot
services seen in network responses. Raw data: `/tmp/js_sweep_results.json`
(not committed). Three exchanges (XQSE, XNBO, XTAD) were then re-probed with
`<script>`, `<style>`, `<meta>` and `<link>` stripped, searching visible text
for Holiday, holiday, Eid, Ramadan, Arafat. XPHS's Checked page
(`pse.com.ph/investing-at-pse/`) was not in the sweep JSON (the sweep tested a
404 URL); its row uses an earlier Playwright run (HTTP 200, 528,057 bytes, no
calendar terms in visible text; the one raw hit was inside a `<style>` block)
and a retest that timed out.

Notes:
- XBOM and XNSE "holiday" matches occur in ~330-byte Akamai 403 bodies whose
  requested URLs contain "holiday"; treated as no calendar content.
- XTAD returned HTTP 403 for the same URL in an earlier spike run
  (`2026-09-19_jsfetcher_spike.md`) and 200 here.
- XQSE's `www.qe.com.qa/trading-calendar` timed out in the sweep and returned
  404 in the probe. The site answers; the path does not exist.
- Several second candidates were apex-domain variants (no `www.`) that failed
  on DNS or certificate errors (XTAI, XQSE, XSGO, XLIM). Those failures reflect
  the candidate URL, not the exchange. The XTAI and XLIM pages named in
  BLOCKED.md `Checked:` lines were therefore not successfully tested.
- Cloudflare and reCAPTCHA appear in the network log of pages that rendered
  fully (XNBO, XTAD, XLIM, XPHS), so their presence alone is not evidence that
  they blocked the request.

## Conclusion
A headless browser resolves none of the 13. For 8 the sweep observed a
blocker unrelated to rendering, so the "JS-rendered" label is wrong for them:
Akamai HTTP 403 (XSES, XBOM, XNSE), Cloudflare 503/403 (XJKT), an
hCaptcha/Perfdrive challenge page (XSGO), and source URLs that no longer
exist on live sites (XTAI, XQSE, XNBO). For the other 5 the sweep found no
blocker and does not refute the earlier JS-rendering findings: XKRX timed out,
XTUN returned 39-byte bodies, and XLIM, XTAD and XPHS returned full pages
without calendar terms in visible text after an 8 s wait. That is consistent
with client-side rendering needing a longer wait or interaction, or with the
tested URL not holding the calendar; it is not evidence of anti-bot blocking.
This sweep used one vantage point, one fixed wait and no network-traffic
analysis for calendar endpoints.
